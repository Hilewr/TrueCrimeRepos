# True Crime Bot

Пайплайн: RSS/сайты → GigaChat (перевод + рерайт + промпт для картинки) →
FusionBrain/Kandinsky или Pollinations.ai (картинка) → очередь → автопостинг в
Telegram-канал по расписанию.

## Деплой на bothost.ru

Никакого отдельного конфиг-файла (вроде `amvera.yml`) тут не нужно — bothost
сам собирает Docker-образ по `requirements.txt` и структуре репозитория.

1. Создай **отдельный** репозиторий на GitHub для этого бота (не смешивай с
   другим ботом) и залей туда всё содержимое этой папки целиком, а не только
   `main.py` — без остальных файлов (`config.py`, `db.py`, `parser.py`,
   `rewriter.py`, `image_gen.py`, `scheduler.py`, `requirements.txt`) бот не
   запустится, `main.py` их импортирует.
2. На bothost.ru → «Создать бота» → выбрать деплой из Git → подключить этот
   репозиторий.
3. В настройках создания бота обычно спрашивают имя стартового файла — укажи
   `main.py` (по умолчанию платформа ждёт `bot.py`, но это настраивается).
4. В разделе **«Пользовательские переменные»** (там же, где сейчас у другого
   бота `RICHADS_PUBLISHER_ID`) добавь переменные из `.env.example`:
   `BOT_TOKEN`, `ADMIN_IDS`, `CHANNEL_ID`, `GIGACHAT_AUTH_KEY`, при желании
   `FUSIONBRAIN_API_KEY`/`SECRET_KEY`, `RSS_FEEDS`, `SEARCH_KEYWORDS` и т.д.
   Сам `.env`-файл в git заливать не нужно (он в `.gitignore`).
5. Нажимаешь «Деплой» — платформа сама соберёт контейнер и запустит бота;
   при новом `git push` пересоберёт автоматически.

**Важный момент, который стоит проверить в панели bothost**: у Docker-хостингов
файловая система контейнера часто пересоздаётся при каждом передеплое —
если это так и здесь, `bot.db` и накопленные ключевые слова будут теряться
при обновлении кода. Проверь в настройках бота, есть ли опция вроде
«постоянное хранилище» / «volume» / «persistent storage», и если есть —
укажи там `DB_PATH` и `IMAGES_DIR` (по умолчанию ниже — просто `data/bot.db`
и `data/images` внутри проекта, поправь под то, что предложит хостинг).

## Установка (локально/на своём сервере)

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:
- `BOT_TOKEN` — токен бота от @BotFather.
- `ADMIN_IDS` — твой Telegram ID (узнать можно у @userinfobot).
- `CHANNEL_ID` — ID канала, куда постить (бот должен быть в нём админом).
- `RSS_FEEDS` — ленты источников через запятую.
- `GIGACHAT_AUTH_KEY` — Authorization key из кабинета GigaChat API
  (developers.sber.ru), бесплатный лимит есть.
- `FUSIONBRAIN_API_KEY` / `FUSIONBRAIN_SECRET_KEY` — необязательно; если не
  указать, картинки будут генерироваться бесплатно через Pollinations.ai.

## Запуск

```bash
python main.py
```

## Автоматический поиск тем (без ручного подбора сайтов)

Поиск не завязан на список конкретных сайтов — вместо этого бот ищет через
**Google News RSS** (бесплатно, без ключа) по ключевым фразам вроде «серийный
убийца» или «cold case murder». Список фраз хранится в БД и:

- при первом запуске заполняется дефолтным набором (или тем, что укажешь в
  `SEARCH_KEYWORDS`);
- раз в `KEYWORDS_REFRESH_HOURS` (по умолчанию сутки) бот сам просит GigaChat
  придумать новые, ещё не использованные запросы — так пул тем расширяется
  без твоего участия;
- посмотреть текущий список — `/keywords`, добавить свою фразу вручную —
  `/keywords <фраза>`, форсировать генерацию новых — `/refresh_keywords`.

Если захочешь всё же жёстко ограничиться конкретными проверенными сайтами —
просто укажи их в `RSS_FEEDS`, они добавятся вместе с автопоиском.

## Переменные окружения на хостинге через git

Раз деплой идёт через репозиторий — `.env` **не должен попадать в git**
(файл уже в `.gitignore`). На практике это значит:

1. Локально/для теста — `.env` с реальными ключами, он лежит только у тебя.
2. На хостинге — те же самые переменные (`BOT_TOKEN`, `GIGACHAT_AUTH_KEY` и
   т.д.) вводятся через панель хостинга (обычно раздел вроде «Environment
   variables» / «Переменные окружения» в настройках приложения), а не через
   файл в репозитории.
3. Код ничего не нужно менять: `config.py` читает `os.getenv(...)` — не важно,
   пришла переменная из `.env`-файла (`load_dotenv()`) или была установлена
   хостингом напрямую в окружение процесса. Если хостинг сам подставляет
   переменные окружения, `.env`-файл на сервере вообще не нужен.

## Как это работает

1. Раз в `FETCH_INTERVAL_MINUTES` (по умолчанию час) бот ищет статьи по
   ключевым словам через Google News (плюс твои `RSS_FEEDS`, если заданы),
   вытаскивает полный текст новых статей (`parser.py`) и кладёт их в БД.
2. Для новых статей (в пределах дневного лимита `POSTS_PER_DAY`) вызывается
   GigaChat: перевод + полный рерайт + промпт для картинки (`rewriter.py`).
3. По промпту генерируется атмосферное фото (`image_gen.py`).
4. Готовый пост становится в очередь с равномерным временем публикации на день
   (`scheduler.py` → таблица `posts`).
5. Раз в `PUBLISH_CHECK_MINUTES` бот проверяет, каким постам пришло время, и
   публикует их в канал.

## Команды администратора (в личке с ботом)

- `/queue` — показать очередь постов, ожидающих публикации.
- `/approve <id>` — оставить пост в очереди (если модерация была нужна).
- `/reject <id>` — снять пост с публикации.
- `/collect` — запустить сбор и рерайт немедленно, не дожидаясь таймера.
- `/keywords` — показать активные поисковые фразы; `/keywords <фраза>` —
  добавить свою.
- `/refresh_keywords` — попросить GigaChat придумать новые поисковые фразы
  прямо сейчас.

## Важные нюансы

- **GigaChat и SSL**: серверы Сбера используют сертификат Минцифры РФ. В
  `rewriter.py` проверка сертификата по умолчанию отключена (`VERIFY_SSL =
  False`) для быстрого старта. Для продакшена правильнее поставить в систему
  сертификат НУЦ Минцифры и включить проверку.
- **Дневной лимит текста**: бесплатная квота GigaChat ограничена — если постов
  много, часть статей может не обработаться (останутся в БД со статусом
  `new` и будут подхвачены в следующий проход, когда лимит освободится).
- **FusionBrain** ограничивает число генераций в день на бесплатном тарифе;
  как только лимит исчерпан, код автоматически переключается на
  Pollinations.ai — это НЕ зеркало, это отдельный бесплатный сервис, качество
  и стиль картинок будут немного отличаться.
- **Копирайт**: системный промпт GigaChat явно требует не копировать
  формулировки оригинала — это не только вопрос стиля, но и юридической
  безопасности канала (пересказ фактов вместо копирования текста статьи).
- Расположи проект и `bot.db`/`images/` на хостинге — 5 ГБ более чем
  достаточно, картинки можно периодически чистить (`images/`), они не нужны
  после публикации.
